It is expected that all members of the group contribute to the project in a fair and equitable manner, and that we will reach out to one another for assistance should the need arise. It is important that members contribute easily-readable “self-documenting” code.

## Team Values

1. All team members are expected to contribute fairly to the project.
2. Team members should communicate regularly and keep each other updated on their progress.
3. If disagreements arise, the team will discuss solutions and make decisions together.
4. Members should notify the team as soon as possible if they are unable to complete a task.
5. Team members should respect each other's opinions and provide constructive feedback.

The project will use the “MERN” stack (MongoDB, Express.js, React.js, [Node.js](http://Node.js)).

## Prerequisites

- [MongoDB](https://www.mongodb.com/docs/manual/administration/install-community/#std-label-install-mdb-community-edition)
- [Node.js](http://Node.js) LTS, including NPM

## Contributing Steps

1. Clone the repo
2. Create an issue
3. Perform work on a new branch
4. Create an \`.env.\` file
5. Install NPM dependencies (`npm i`)
6. Make and commit changes incrementally
7. Communicate with teammates before making major changes to shared files.
8. Commit messages should be clear and descriptive so other team members can understand what was changed. [Use conventional commits](https://www.conventionalcommits.org/en/v1.0.0/)
9. Adding relevant tests
10. Team members should test their code locally before pushing changes to GitHub.
11. Ask teammates for help when encountering issues instead of making major changes without discussion.
12. Run ESLint and Prettier prior to commit
13. Resolve any conflicts using merge
14. Report bugs or issues to the team as soon as they are discovered.
15. Push, then submit a pull request, linking to the issue number (Closes \#\<number\>) in the PR description.
16. Watch for CI, wait for review on the PR, and fix the findings if necessary
17. When merging the PR, use `Create a Merge Commit`

## Daily Standup

1. Give a quick update on what you have completed and what you plan to work on next.
2. Let the team know if anything is blocking your progress.
3. Notify the team ahead of time if you cannot attend a meeting.

## Building & Testing

`npm run build`  
`npm test`

## Sprint Cadence

1. Sprints will have a 2-week cadence.
2. At the beginning of each sprint, the team will discuss and assign tasks based on priority.
3. Each team member should complete their assigned tasks before the sprint deadline.
4. At the end of each sprint, the team will review completed work and discuss any challenges.
5. Any unfinished tasks will be discussed and moved to the next sprint if necessary.
